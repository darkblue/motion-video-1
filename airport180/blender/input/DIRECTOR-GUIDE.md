# 《一座国际机场是如何建成的？》导演执行分镜 V1

**片长：**180秒｜1920×1080｜30fps｜总计5400帧｜25镜头  
**工程唯一依据：**上一阶段 `airport-project.json`、`contracts.json`、`approval-workflow.json`、`construction-phases.json`。  
**项目：**新岚国际机场，虚构一期1500万人次，初步估算20亿美元，60个月示意周期。  

## 导演视觉总则

1. **真实世界坐标不动，相机动。** 机场东西向跑道、其北侧平行滑行道/机坪、再向北航站楼/陆侧的空间关系不得因分镜改变。
2. **建成全貌是唯一主资产。** 建设效果通过对象显隐、施工构件的独立替换表示。禁止每幕重新生成机场。
3. **全片两条视觉线索：** 机场三维建设线（Blender）和文件/审批/价格线（Remotion）；使用“纸张变模型”“模型变图纸”的图形匹配连接。
4. **俯视与等距为主。** Blender正交相机使用 orthographic_scale 控制视野，不使用毫米焦距；仅透视近景指定50/65/70mm等焦距，具体取景依据模型尺寸调节。
5. **不强行展示飞机着陆。** 最后一镜仅在已经定义的跑道直线段做符号性运动，不模拟进近净空、起落航迹或未经复核的滑行转弯。
6. **合同线与审查线不同色。** 业主与设计咨询/工程师/施工总包分别有合同；工程师与总包之间仅有业务往来而非直签合同。
7. **专业审查优先。** 高楼禁区、碰撞、净空均为演示层几何检查；不能声称达到了真实机场设计审批标准。

## 音画与剪辑规则

- 音乐：轻节奏原创/授权无歌词氛围音，旁白始终优先；环境音选用许可音效。
- 配音：普通话，理性科普口吻；单镜头旁白应依据实际TTS长度允许微调，不能强制拉伸语音。
- 字幕：屏幕底部安全区内单至双行，每行优先不超过16个汉字；术语卡片为另一图层，不能与字幕重叠。
- 画面上尽量一次只解释一个工程关系。数字、箭头、角色、图例尽量与旁白关键词同步出现。
- 转场优先同一图形匹配、相机推移和遮罩，避免频繁炫技型转场。
- 固定字幕/旁白时间不等于逐字对齐；应在配音生成后使用实际音频或对齐工具修订SRT。

## 25镜头执行表

### S01｜0–20秒｜机场需求增长与议案


- **000–007秒 城市需求增长**：正俯视城市/旧机场抽象示意；城市需求点逐个亮起；旧机场容量计数上升。
  - 旁白：当航空需求快速增长，原有机场可能逐渐达到容量上限。
  - 屏幕字幕：需求增长 · 既有机场容量不足
  - 转场：淡入；检查点：旧机场为独立插画，不使用新机场主模型

- **007–014秒 建设议案**：政府会议桌中景；旧机场小图缩至左下，项目建议书由右侧滑入。
  - 旁白：政府和机场业主据此提出新机场建设议案。
  - 屏幕字幕：建设议案 Airport Development Proposal
  - 转场：图形匹配；检查点：显示Proposal文件和机场业主，避免虚构具体国家机构

- **014–020秒 决策门槛**：议案特写；文件盖章→转成项目主时间轴起点。
  - 旁白：批准启动研究，并不意味着马上开工。
  - 屏幕字幕：项目启动 ≠ 开工许可
  - 转场：遮罩接续；检查点：显示仅为启动研究，不意味着已经批准施工

### S02｜20–45秒｜咨询设计与总体规划


- **020–027秒 选址与需求**：规划地图俯视；三个候选地块出现，聚焦最终示意机场用地。
  - 旁白：咨询团队首先预测需求，研究选址与建设条件。
  - 屏幕字幕：需求预测 · 选址研究
  - 转场：地图擦除；检查点：场址非真实地理位置；不虚构城市建筑靠近跑道

- **027–036秒 总平面生长**：机场总体俯视→等距鸟瞰；严格按JSON坐标，跑道→平行滑行道→连接滑行道→机坪→航站楼显现。
  - 旁白：随后确定跑道、滑行道、机坪和航站楼的空间关系。
  - 屏幕字幕：机场总体规划 Airport Master Plan
  - 转场：同形元素变换；检查点：必须是唯一机场模型；只控制显隐，禁止重建对象

- **036–045秒 设计成果**：机场模型左、成果文件右；模型保持位置不变；FS/MP/Concept/Preliminary四张文件沿时间轴出现。
  - 旁白：可研、总体规划与初步设计逐步形成工程方案。
  - 屏幕字幕：可研 · 总体规划 · 初步设计
  - 转场：分层叠加；检查点：成果文件名称与不同项目工作阶段不强行一一对应

### S03｜45–65秒｜投资估算


- **045–053秒 投资构成**：机场模型缩小到左侧，费用卡片右侧；土建/航站楼/机电/专用设备等条块累计增长。
  - 旁白：咨询机构根据方案编制初步投资估算。
  - 屏幕字幕：示例投资估算 20亿美元（虚构）
  - 转场：推拉切换；检查点：示例估算20亿美元，不把比例作为真实项目数据

- **053–060秒 融资决策**：预算表特写；估算文件移交业主，出现融资与预算审批印章。
  - 旁白：投资估算用于预算、融资和投资决策。
  - 屏幕字幕：投资估算 → 预算与融资决策
  - 转场：文件接力；检查点：投资估算用以决策；避免出现已签固定总价

- **060–065秒 价格区分**：三列价格卡片；初步估算/合同中标价/结算金额三列依次点亮。
  - 旁白：但估算、合同中标价和最终结算价并不相同。
  - 屏幕字幕：估算 ≠ 中标合同价 ≠ 最终结算价
  - 转场：卡片联动；检查点：不宣称三者金额相等

### S04｜65–95秒｜总包与工程师招标


- **065–073秒 招标模式**：项目组织图俯视；Design-Bid-Build居中，EPC/DB作为右侧对照。
  - 旁白：本片以业主设计、施工总承包招标为例。
  - 屏幕字幕：主线：Design–Bid–Build
  - 转场：平移；检查点：本片后续只采用DBB；切换展示不改变责任分工

- **073–082秒 招投标**：流程横向跟拍；资格预审→发标→投标→评标→授标逐节点亮。
  - 旁白：业主组织施工总包及工程师服务招标，评估技术与报价。
  - 屏幕字幕：发标 → 投标 → 评标 → 授标
  - 转场：节点接力；检查点：施工总包和工程师/监理招标可分别组织

- **082–090秒 合同关系**：固定业主居上，三家单位居下；只绘制owner→designer/engineer/contractor合同实线。
  - 旁白：随后分别签署设计咨询、工程师服务和施工合同。
  - 屏幕字幕：谁与谁签约？合同关系必须明确
  - 转场：图表展开；检查点：无engineer与contractor合同线；采购合同为contractor→supplier

- **090–095秒 文件与合同区别**：合同图特写；总包→工程师虚线文件箭头；工程师→总包审查反馈。
  - 旁白：工程师审查承包商文件，但双方不因此直接签约。
  - 屏幕字幕：合同线 ≠ 审批线
  - 转场：颜色匹配；检查点：提交线不得绘制为合同线

### S05｜95–125秒｜深化设计/BIM


- **095–102秒 深化设计入口**：由机场鸟瞰推进到既有航站楼；镜头向航站楼移动，其他机场对象保留固定世界坐标。
  - 旁白：施工前后，设计团队持续细化航站楼各专业图纸。
  - 屏幕字幕：设计深化 Detailed Design
  - 转场：镜头连续运动；检查点：只移动摄像机，不平移航站楼位置

- **102–112秒 BIM图层**：航站楼等距近景；结构→建筑→暖通→电气→弱电分层抬升；每层对应唯一集合。
  - 旁白：建筑、结构、机电和弱电系统需要协同设计。
  - 屏幕字幕：BIM多专业协同
  - 转场：层级展开；检查点：图层仅可视化，归位坐标严格相同

- **112–120秒 碰撞与协调**：管线局部特写；一处风管与桥架冲突标红，调整预先设计的桥架局部路径。
  - 旁白：BIM检查能够提前发现管线碰撞和空间冲突。
  - 屏幕字幕：碰撞检查 Clash Detection
  - 转场：焦点推近；检查点：只对演示构件做可控调整；不能随机穿楼板

- **120–125秒 图纸审查**：BIM模型回收，旁侧图纸卡片；分层回归→图纸提交→批注→修订→审查状态。
  - 旁白：问题解决后，相关图纸按合同程序提交审查。
  - 屏幕字幕：提交 → 审查 → 修订
  - 转场：模型到图纸匹配；检查点：审查后图纸不代表全部工程可直接开工

### S06｜125–145秒｜品牌和设备审查


- **125–133秒 供应商报审**：设备图标与资料卡片；技术参数/厂商资质/符合性矩阵汇聚到总包。
  - 旁白：设备采购前，供应商准备技术资料，由总包统一报审。
  - 屏幕字幕：Material Submittal 技术报审
  - 转场：文件汇聚；检查点：使用approval-workflow.json A1/A2，设备为示例航显系统

- **133–140秒 审核分支**：工程师审查决策菱形；审查→合格前进/不符合退回A2，黄色提示条件性业主确认。
  - 旁白：工程师核对技术规范，不符合要求的资料必须修改。
  - 屏幕字幕：审查通过 / 退回修改
  - 转场：路径高亮；检查点：按JSON A3分支；owner A4标注if required

- **140–145秒 采购前置**：采购订单与生产线；条件满足→采购合同→制造图标；不自动默认批准。
  - 旁白：完成必要确认后，总包才能按约组织相应采购。
  - 屏幕字幕：按合同权限确认后采购
  - 转场：状态交接；检查点：业主确认仅在合同要求时执行

### S07｜145–170秒｜施工/专用系统联调


- **145–153秒 工程并行**：固定机场俯视全景；底层飞行区施工与上层航站楼施工在同一时间轴并行。
  - 旁白：现场施工通常是多专业、多区域交叉推进。
  - 屏幕字幕：飞行区 · 航站楼并行建设
  - 转场：时间轴叠加；检查点：以施工阶段控制显隐；不用镜头随机移动设施

- **153–161秒 安装系统**：航站楼剖面与设备节点；屋面完成后再出现设备，BHS/航显/安检等依次定位。
  - 旁白：土建和机电条件具备后，机场专用设备陆续安装。
  - 屏幕字幕：设备安装 · 系统集成
  - 转场：剖面擦除；检查点：系统部署节点固定；不要让设备飘在跑道上

- **161–170秒 联调联试**：AODB中心向各系统数据流；AODB节点出现，FIDS/BHS/BRS/DCS接口逐条高亮，最后测试通过。
  - 旁白：之后还要完成设备测试、系统联调和综合验证。
  - 屏幕字幕：测试与调试 Testing & Commissioning
  - 转场：线条生长；检查点：示意数据关系非完整接口规范；测试不能等同最终许可

### S08｜170–180秒｜ORAT与交付


- **170–176秒 ORAT与批准**：航站楼运行准备看板；测试/流程演练/人员培训/监管批准按序显示。
  - 旁白：机场还需要运营准备、联合演练和必要的监管批准。
  - 屏幕字幕：ORAT · 监管批准
  - 转场：检查项收束；检查点：审批是法定要求的条件节点，不由工程师代替监管

- **176–180秒 开航收尾**：机场最终等距全景；航站楼点亮，飞机仅在跑道指定直线段示意移动，标题渐入。
  - 旁白：完成交付，机场才真正迎来首航。
  - 屏幕字幕：从建设愿景到正式起航
  - 转场：淡出到片尾；检查点：不生成未经校核的降落进近路径或滑行转弯

## 必须审核的关键帧

- 01:02、01:12、02:00：同一航站楼各层模型位置不漂移。
- 02:13、02:20：报审退回分支及条件性业主确认。
- 02:25、02:33、02:41：工程顺序与设备安装前提。

## 交付给动画程序员的要求

1. 导入本包JSON，不得单独人工重建机场布局。
2. 每个镜头的时间以30fps整数帧为准；若TTS长度不匹配，则重调镜头节奏并更新JSON、SRT。
3. 输出全部镜头首帧、中帧、末帧缩略图；自动生成接触表（contact sheet）。
4. 先完成S02的27–36秒、S04的82–95秒、S05的102–120秒三个高风险测试镜头。
5. 没有真实三维BIM素材时使用受控占位分层示意，不要伪装真实机场施工图。
